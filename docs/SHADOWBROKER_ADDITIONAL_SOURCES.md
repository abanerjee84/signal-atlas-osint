# Additional ShadowBroker sources and features for Signal Atlas

Reviewed 2026-11-08 against upstream commit [`e6e8f6e7b709666d128f5c25ccac144b0efda997`](https://github.com/BigBodyCobain/Shadowbroker/tree/e6e8f6e7b709666d128f5c25ccac144b0efda997) and the current Signal Atlas source registry. This is a source-code and provider-documentation assessment, with three endpoint checks noted below. It does not establish that every upstream feature works in a deployed instance. No product changes, commits or pushes are part of this review.

The strongest next additions are official hazard data, explicit C2 feeds, fishing-event history, public infrastructure references and location-based watch rules. Several advertised features extend capabilities Signal Atlas already has; those should share its provenance and evidence model instead of becoming duplicate feeds.

## Ranked candidates

Priority and effort are implementation recommendations, not provider claims. Low means an adapter using existing storage/UI patterns; medium means a new geometry, identity or measurement workflow; high means substantial processing or permission design. Public access does not itself grant redistribution rights.

| Priority / effort | Addition | What to incorporate | Access, evidence and limits |
| --- | --- | --- | --- |
| P1 / low | **Feodo Tracker and URLhaus** | Add explicit malware C2 endpoints and malicious-URL observations alongside existing ThreatFox and DShield data. Keep first/last seen, malware family and provider references. | Upstream has both adapters in [malware.py][S1]. During this review Feodo's JSON endpoint returned HTTP 200 with five entries; the URLhaus endpoint returned HTTP 401 without credentials. Confirm current URLhaus authentication and terms. Do not copy the upstream geographic jitter or fallback of unknown countries to Afghanistan: preserve unknown locations and label country aggregates. |
| P1 / low | **NOAA/NWS severe-weather alerts** | Retain alert polygons, effective/expiry times, severity and original warning URLs. Useful around airports, ports, ground stations and infrastructure. | [earth_observation.py][S2] fetches NWS active alerts. The [NWS API documentation](https://www.weather.gov/documentation/services-web-api) describes public APIs and required identifying User-Agent. This is US/jurisdictional coverage, not worldwide weather warnings. |
| P1 / low | **NOAA SWPC space weather** | Add K-index and solar/radio event timelines beside GNSS accuracy cells and radio observations. | Upstream uses SWPC planetary K-index and edited-events JSON in [earth_observation.py][S2]. [NOAA's product catalog](https://www.swpc.noaa.gov/products-and-data) is the primary reference. Correlation supplies context; it does not prove that a navigation anomaly came from a solar event or intentional interference. |
| P1 / medium | **More public traffic-camera catalogs** | Extend the existing TfL directory with transport-agency adapters and per-provider timestamps/status. Start with a small documented set such as Caltrans and NYC, then add other regions. | The upstream [camera pipeline][S3] includes multiple US agencies, Singapore, Spain, Austria, Canada, Australia and the Netherlands. Some providers require keys or offer snapshots rather than video. Check each agency's reuse terms; do not imply that a listed camera works or that retained metadata includes historical footage. |
| P1 / medium | **Public infrastructure registries** | Add power plants, verified data-center sites and licensed submarine-cable geometry to the existing reference-layer system. Link nearby reports without treating proximity as an outage. | Upstream [infrastructure.py][S4] loads local power-plant and data-center files; cable geometry is also a [static asset][S5]. These are references, not live feeds. Obtain source data and rights directly. [WRI's database description](https://www.wri.org/research/global-database-power-plants) covers plant locations and attributes; preserve dataset version and attribution. Cable and data-center redistribution permissions need separate review. |
| P1 / medium | **Area and entity watch rules** | Let analysts save an area, route or entity; alert on an aircraft/vessel entering it, a new nearby report, or a new matching hazard. Reuse retained monitoring history and investigation cases. | This extends the upstream area-of-interest and entity-trail workflows ([SAR AOIs][S6], [entity profiles][S7]). Signal Atlas currently has webpage-change watches and reporting surges; it lacks a general spatial rule engine. Add deduplication, cooldowns, source-age checks and inspectable evidence before notifications. Missing telemetry is a coverage gap, not an event. |
| P2 / medium | **Global Fishing Watch activity/events** | Extend the existing GFW vessel-identity integration to fishing activity, encounters and gaps, with interval/geometry evidence and links to individual vessels. | Upstream [geo.py][S8] calls GFW's event API. [Official API workflows](https://globalfishingwatch.org/our-apis/documentation/) distinguish activity, identity, encounters and risk. A token is required, and the documentation restricts API use to non-commercial purposes. Apparent fishing and AIS gaps are provider assessments, not proof of illegal activity. |
| P2 / low–medium | **KiwiSDR directory and PSK Reporter** | Replace radio configuration-only discovery with cached public receiver metadata; add recent digital-mode reception reports as a separate observation class. | Upstream [KiwiSDR][S9] uses a public directory mirror and a bundled fallback, so distinguish cached references from current receiver availability. [PSK Reporter][S10] uses its documented public query endpoint and converts Maidenhead grids to approximate coordinates. See [PSK API guidance](https://pskreporter.info/pskdev.html). Keep directory access, tuning and received-signal observations separate. |
| P2 / medium | **TinyGS satellite telemetry** | Add LoRa reception/status metadata to the existing orbital estimates and SatNOGS references. | [tinygs_fetcher.py][S11] merges CelesTrak propagation with TinyGS metadata. The TinyGS endpoint returned HTTP 403 during this review; access must be established before promising this layer. Its code can fall back to propagated satellites without TinyGS confirmation, so SGP4 positions must not be presented as verified radio receptions. |
| P2 / low–medium | **Rail positions** | Add regional train observations and history using the current vessel/aircraft model, with separate provider clocks and operator identities. | [trains.py][S12] uses Amtraker for US passenger trains and Digitraffic for Finland. It does not provide general European or worldwide train coverage. Prefer official regional feeds when available; retain per-provider limits and licensing. |
| P2 / medium | **OpenAQ and Smithsonian volcano data** | Add timestamped air-quality measurements and volcanic activity/reference records to environmental monitoring. | [earth_observation.py][S2] uses OpenAQ v3 and Smithsonian GVP WFS. [OpenAQ requires an API key](https://docs.openaq.org/using-the-api/api-key); use current location/sensor/measurement resources rather than assuming the upstream `lastValue` field still works. [GVP supports WFS feature formats](https://volcano.si.edu/database/webservices.cfm). A volcano's registry location is not a current eruption, and a station reading is not country-wide air quality. |
| P2 / medium | **Sentinel imagery and SAR scene discovery** | Add a place/area imagery card, cloud/date filters, scene footprints and before/after selection; preserve acquisition dates in cases. | Upstream [SAR catalog client][S13] uses Alaska Satellite Facility metadata search. [Copernicus Sentinel-2 documentation](https://dataspace.copernicus.eu/data-collections/copernicus-sentinel-missions/sentinel-2) describes optical observations and open data access. Catalog metadata, actual image assets and derived change measurements need distinct records. Optical imagery is cloud-limited and is not a live camera. |
| P2 / medium–high | **Published water/disturbance and emergency-mapping products** | Begin with OPERA DSWx surface-water products and published Copernicus EMS/UNOSAT assessments for an analyst-selected area, then add validated change calculations. | The pinned [SAR product client][S14] fetches catalog metadata for DSWx and DIST-ALERT. [NASA JPL's catalog](https://www.jpl.nasa.gov/go/opera/products/) distinguishes water, disturbance and displacement products and their coverage. Metadata availability alone is not a detected flood or damage measurement; asset processing, quality flags and a baseline are needed. |
| P2 / medium | **Passive recon and external entity enrichment** | Extend current RIPE, GreyNoise, SANS, OFAC and case graphs with structured DNS/RDAP, certificate-transparency and externally sourced ownership links. Add source-specific dates and match confidence. | Upstream [recon helpers][S15] and [entity profiles][S7] show the workflow. Signal Atlas already has some adapters and manual resource links, so this is an integration upgrade. Keep it operator-authenticated, quota-bounded and passive; distinguish a name match from a verified identity. Start read-only before considering agent-issued mutations. |
| P3 / medium | **Supplier exposure and specialist narrative/health data** | Add a reviewed supplier registry with explainable hazard proximity, then opt-in EUvsDisinfo narratives or wastewater monitoring only if the analyst workflow needs them. | Upstream's [supplier model][S16] is a small hard-coded facility list with heuristic proximity rules, not a global dependency model or validated outage probability. [FIMI][S17] consumes EUvsDisinfo RSS; [EUvsDisinfo explains its editorial scope](https://euvsdisinfo.eu/about/), so preserve attribution rather than assigning neutral truth labels. [WastewaterSCAN code][S18] uses public project endpoints; formalize dataset permissions, sample dates and reporting gaps first. These are separate optional modules, not one combined risk score. |

## Implementation order

1. **First:** Feodo, authenticated URLhaus where permitted, NWS, SWPC, and a spatial watch-rule engine. These add distinct evidence or make the current data more useful without requiring a new processing platform.
2. **Then:** a small camera expansion, infrastructure references, GFW event history and public radio discovery. Use the existing source-health, reference-registry and monitoring-history patterns.
3. **After a data-processing design:** optical/SAR imagery, published flood/disturbance products and supplier exposure. Keep every measurement's units, acquisition time, geography and uncertainty.

## Claims that should not be copied into Signal Atlas

- **Global millimetre-scale SAR change detection:** the pinned product adapter does not deliver this. Its OPERA list contains DSWx and DIST-ALERT products, not a DISP measurement pipeline. The EGMS path emits a coverage/link record instead of ingested motion measurements; the GFM function currently returns an empty list. [Pinned implementation][S14]. NASA's [DISP and DSWx products](https://www.jpl.nasa.gov/go/opera/products/) have different purposes and coverage. [Copernicus states that EGMS products are available through its Explorer](https://land.copernicus.eu/en/products/european-ground-motion-service). Treat measured deformation as a later validated integration.
- **FLIR/NVG/CRT views:** visual styling does not add thermal, night-vision or radar sensing to an ordinary map or optical image. Keep any such styles labelled as display effects.
- **Exact live fleet locations from reporting:** USNI/GDELT-derived positions are dated, approximate reporting evidence, not AIS telemetry.
- **Guaranteed private InfoNet/mesh communications:** this is a separate communications product with a larger trust and security scope. It is not a required intelligence-feed upgrade.
- **Duplicated baseline sources:** USGS, FIRMS, GDELT, ACLED, AIS, CelesTrak, SatNOGS, TfL, Telegram public previews, IODA/RIPE, CISA, ThreatFox and Shodan host lookup already exist in some form. New provider coverage or workflows can still extend them, but they should not inflate an independent-feed count.

All recommendations should be implemented as original adapters to the underlying providers. ShadowBroker advertises an AGPL license; do not assume that copying its implementation into Signal Atlas is equivalent to independently using the same public dataset. This report is an implementation assessment, not a legal determination.
