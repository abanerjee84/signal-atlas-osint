# Conflict and military source audit

Checked **11 October 2026** against first-party pages and ordinary unauthenticated HTTP responses. No API keys, login, challenge bypass, proxy rotation, or server changes were used. An HTTP 200 response alone was not treated as a successful feed: item structure, publication dates, and usable content were inspected.

## Findings that affect the map

Liveuamap can supply geolocated conflict reports beyond Ukraine through its public regional pages. Its HTML already carries each report's original source link, location, publication timestamp, and coordinates. This is more useful than collecting headline mentions alone. However, regional timelines can include earthquakes and several months of history; collecting a page today does not make all its records current. [Liveuamap Ukraine](https://liveuamap.com/), [Asia](https://asia.liveuamap.com/), [Myanmar](https://myanmar.liveuamap.com/), [Sudan](https://sudan.liveuamap.com/).

Military coverage needs both incident reporting and slower reporting on forces, equipment, exercises, procurement, and deployments. The verified publishers below add Africa, Myanmar, Afghanistan/Pakistan, the Middle East, naval affairs, and military technology. They supplement rather than replace the existing BBC, Guardian, UN News, DVIDS, NATO, UK Ministry of Defence, and regional news feeds in `backend/connectors/registry.py` and `world_feeds.py`.

Conflict assessments are a separate kind of evidence. ISW, Crisis Group, and CFR provide analysis; UCDP provides coded historical events. Their assessment dates and limitations must remain visible, and none should be recast as freshly observed battlefield activity. [ISW](https://understandingwar.org/), [Crisis Group feed](https://www.crisisgroup.org/rss.xml), [CFR methodology](https://www.cfr.org/global-conflict-tracker/methodology), [UCDP download center](https://ucdp.uu.se/downloads/).

The public HTML currently contains a base64-encoded JSON initializer, observed as `var ovens = '…'`. Decoding it without evaluating JavaScript yields an object with `venues`. Each venue contains `id`, `name`, `timestamp`, `source`, `lat`, `lng`, `location`, `link`, `cat_id`, `picpath`, `points`, and `moreSources`. The variable name is an implementation detail and may change. Parsers should validate a bounded candidate payload by its structure, cross-check records against visible `post-<id>` event cards, and fail visibly when the structure changes. [Public Ukraine HTML](https://liveuamap.com/), [public Israel–Palestine HTML](https://israelpalestine.liveuamap.com/).

Use the source's numeric event ID to deduplicate cross-posted regional records. Sort by the supplied timestamp, preserve publication time, reject invalid coordinates, and retain a conservative geographic precision label. Do not ingest `fvObjects` as events: this separate initializer includes static landmarks and military facilities. Do not interpret `cat_id`, colors, or icon names as a documented military taxonomy without explicit text evidence. [Public Ukraine page](https://liveuamap.com/), [public Asia page](https://asia.liveuamap.com/).

Liveuamap's [Terms of Use](https://liveuamap.com/about#terms) permit reuse of its data/maps with attribution, while third-party social content remains subject to the original source's terms. Its [robots file](https://liveuamap.com/robots.txt) returned only a sitemap declaration at audit time. This is not a guarantee of future availability. Collect bounded headline records and source links, cache responses, and back off on blocking rather than harvesting media or full social threads.

- [ReliefWeb guessed RSS](https://reliefweb.int/updates/rss.xml) returned 202 with an empty body, [UN Peacekeeping guessed RSS](https://peacekeeping.un.org/en/rss.xml) and [ICRC guessed RSS](https://www.icrc.org/en/rss.xml) returned 404. Do not register these guessed paths as feeds.

## Integration priorities

1. Add bounded, cached collection of working Liveuamap regional HTML, with original timestamps, explicit source links, cross-region deduplication, and conflict-only filtering. Prioritize geographic coverage rather than filling the map with duplicated Ukraine reports.
2. Add the verified military and regional feeds, avoiding existing registry duplicates. Route actual kinetic/deployment/weapon/exercise reporting to Military OSINT, and diplomacy/protests/elections/conflict policy to Geopolitics. Mixed feeds need article-level classification.
3. Add ISW as a public HTML assessment source; reuse Crisis Group's existing working RSS. Keep CFR and UCDP as deliberate background/history enrichment, not simulated real-time activity.
4. Treat Analysis and anomaly alerts as derived findings with source-record links and an explained comparison window. A rise in reporting volume is a coverage anomaly; it must not be described as a proven rise in attacks without incident-level evidence. Aggregator copies and official claims must remain distinguishable from independent corroboration.

Accessibility results can change. Source health should distinguish a working response, usable records, no recent relevant reports, parsing failure, and blocked access. An empty category is not evidence that no conflict exists.

A follow-up on 11 October found Premium Times serving an HTML/JavaScript cookie challenge instead of its earlier valid feed. The collector does not execute it or bypass it. A later Myanmar politics snapshot failed date/record validation while the military selector retained valid evidence. Both sources retain previous records and expose their current failure state.
