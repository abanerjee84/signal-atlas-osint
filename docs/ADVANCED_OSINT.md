# Advanced investigation workspace

Open **Investigate** in the world map header, or `/advanced.html`. Connect using the existing `OSINT_ADMIN_TOKEN`, which is held in tab memory and cleared on reload. The token is separate from provider credentials. No additional social-media keys are required.

The implementation follows [AOSINT-SRS-001](../ADVANCED_OSINT_SPEC.md) as a separate specification; it does not replace `BUILD_CONTRACT.md`. All eleven specification modules have a working initial screen and versioned API. Cyber also has a dedicated **Threat actors & campaigns** screen, with four source catalogs, documented relationships and report matches; see [THREAT_INTELLIGENCE.md](THREAT_INTELLIGENCE.md). Provider availability, permission requirements and the remaining production acceptance work are listed below.

## Research workflow

1. Create a case with a research scope. Search collected records and use category, source, language, country and UTC publication filters.
2. Save evidence to the case. Its snapshot and SHA-256 remain unchanged when an upstream record changes. Open source links to check context.
3. Select records for deterministic comparison or optional OpenRouter analysis. Correlation weights and the evidence packet are recorded. A numerical association score is not a causal probability.
4. Inspect entity relationships. Reported co-mentions mean that the same record references both entities; they do not establish an alliance, ownership, movement or attack. Every edge exposes supporting source records. Analyst relationships must include evidence and a stated basis.
5. Add authorized geographic, media or document evidence. Record uncertainty, acquisition dates and permissions. Add private notes and use case timeline, graph and exports for review.

## Worldwide news coverage

Twelve additional public feeds have been added: UN News, Africanews, MercoPress, Buenos Aires Herald, CNA World, CNA Asia, RFI, ABC Australia, Euronews and The Guardian's Africa, Americas and Asia feeds. With the subsequent cyber additions, the legacy collector has 57 connectors, including 28 geopolitical connectors and four new cyber feeds. The combined registry has 81 entries, including manual resources, public APIs and four reference catalogs; registry entries are not a count of functioning live feeds.

The new feeds were fetched and checked for usable RSS/Atom content. Mixed feeds use a documented English topic rule to select governance, diplomacy, conflict, security, humanitarian, climate, disaster and economic reporting. This rule can miss relevant items and accept incidental mentions. The source directory describes selection and regional coverage. ABC is labelled as selected international and political headlines from its general feed. An initial correction of 38 off-topic mixed-feed reports was archived under `data/corrections/` before those reports were removed from the active dataset.

Existing map collection, publisher origins, country mentions and source-linked map relationships continue to work. Country mentions are context, not proven incident coordinates. Identical articles delivered through multiple publisher feeds are not independent corroborating sources. Headlines/excerpts remain subject to publisher terms; CNA expressly limits its RSS use to personal, non-commercial purposes.

## Architecture and storage

`backend/advanced/` contains the schemas, shared repository, processing, geographic validation, media, website monitoring, public-provider adapters, jobs, analysis and API interfaces. Migration 004 projects legacy reports into `external_records`, adds FTS triggers and creates investigation tables. The projection is the explicit shared interface for new modules. Existing endpoints remain compatible.

The existing collector also runs investigation jobs under a separate lease. Background work is persisted as queued/running/completed/failed/cancelled jobs. Processing batches are limited to 200 records, pending provider/AI work to four jobs, and individual jobs to 180 seconds. Aviation and maritime observations are searchable but excluded from text narrative extraction. Source monitors are excluded from public narrative analysis.

The API and worker serialize schema inspection and migrations. `START.bat` stops this checkout's recorded process trees and recovers interrupted leases only when the database is inside the checkout's `data` directory. External/shared database leases retain their normal expiry. Startup checks prevent replacing unrelated processes on occupied ports.

Images are stored as private generated identifiers outside frontend assets. Browser rendering uses text nodes and validated links. Development file serving denies backend data, scripts, deployment files and environment files; runtime data directories are excluded from live reload.

RIPEstat and IODA use fixed provider endpoints, not scans of the supplied address.

## Backup and recovery

The existing backup service now creates a bundle containing a transactionally consistent database, active media and a SHA-256 manifest. Secrets are excluded. As before, bulk public discussion snapshots are excluded from recoverable archives; evidence deliberately saved in private cases follows case retention policy. Source-monitor snapshots are included in the database.

```powershell
.\.venv\Scripts\python.exe scripts\backup.py --destination data\backups --keep 7
# Restore to a NEW directory; the command refuses an existing target.
.\.venv\Scripts\python.exe scripts\backup.py --restore data\backups\<bundle> --destination data\<new-restore-directory>
```

Ubuntu uses the existing daily backup timer. Set `OSINT_DATABASE=/var/lib/osint/osint.sqlite3` and `OSINT_EVIDENCE_DIRECTORY=/var/lib/osint/evidence` in `/etc/osint/osint.env`. Preserve ownership by the service user. Restoring the operational database requires stopping the services, checking the restored bundle, and setting database and evidence paths together. Restoration commands never overwrite the running database.

## Verification and remaining acceptance

The backend suite has 135 passing tests, including 47 advanced-module cases; the two existing aircraft tests and production build also pass. Tests cover private access, local indexed search, citations, immutable evidence, permissions-aware exports, file validation, geographic bounds, SSRF/DNS pinning, versioned monitoring, durable jobs, free-provider cache, migration concurrency and media-inclusive restore with tamper rejection.

`advanced-benchmark.json` records measurements against the retained live database on Windows: local search p95 51 ms and source directory p95 95 ms, ten sequential samples per operation. External ingestion and model latency are excluded. Real backup restoration passed integrity and hash verification. A backup created during live development revealed a file-watcher crash; runtime-directory exclusions address it.

Production acceptance on an Ubuntu server with 8 GB RAM, representative concurrent users, disk pressure, sustained ingestion and the production HTTPS/CSP configuration is still required. Local timings do not certify that environment. Optional paid/restricted providers, city geocoding, multilingual sentiment models, automated document acquisition and C2PA remain conditional or unsupported as stated above. This implementation does not certify source claims or authenticity merely because a feed, graph or model produced a result.

Live verification also completed RIPEstat routing for the public address `8.8.8.8` and a citation-validated OpenRouter analysis of two public news records. The latter used `openrouter/free`; no private case notes were sent. Queue-inclusive elapsed times were 14 and 35 seconds respectively, recorded in `advanced-provider-verification.json`. Real browser checks covered searching regional news, creating/retrieving a case, saving two source snapshots, adding a private note and displaying the case graph. Media signature/hash/metadata checks were exercised through the API and the stored screenshot was inspected in the browser. The browser extension lacked local-file selection permission, so the automated file chooser could not select the upload; ordinary user file selection was not tested by that extension.
